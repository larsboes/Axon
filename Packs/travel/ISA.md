# ISA · travel

The travel feature's state of record: transit (journey search, split-ticketing,
reliability), punctuality (the delay histogram behind it), and the travel Pack that
plans on top of them. This file replaces the GitHub issues that used to hold this
backlog and the status list in `design/travel-prd-2026-08-12.md` §8; that document
stays as the reasoning that produced the work, not as a list of what is left.

## Problem

The search engine is done. What is left is that the system computes numbers it then
throws away, and cannot prove the parts it depends on still work.

`capabilities/punctuality` keys its cells on DB's open-data vocabulary — `RB`, `RE`,
`ICE`. `capabilities/transit` sends whatever its rail backend calls the train. dbnav
reads `produktGattung`, which *is* that vocabulary. dbweb reads
`verkehrsmittel.kategorie`, which is HAFAS's own: the identical RE5 Bonn→Köln arrives
as `DRB` and finds no cell. dbweb is the default, so on the default path every regional
leg silently loses its `on_time_probability`, and any journey whose arriving leg at a
transfer is regional scores no `reliability` at all — one missing term voids the whole
product by design. `delay_risk_score` has been degrading the same way far longer; it
only looked healthy because the journey-level lookup reads the *final* leg, which on a
Bonn→Berlin search is an ICE and does resolve.

Separately, punctuality exists to parse someone else's binary format, and the parser is
the one component with no test. Its 29 unit tests never open a file, so every arrow bump
is hand-verified with a throwaway harness or waved through on the changelog.

## Vision

A journey search on the default backend answers with a reliability figure that is
measured or explicitly absent, never quietly zero; and the parser that feeds it proves
itself on every build rather than on the day someone remembers to check.

## Out of Scope

- A fitted delay curve. The originating issue proposed one with three guessed constants;
  it was not built and is not wanted. Every factor is an exceedance read off the stored
  histogram.
- Recording live HAFAS responses as demo fixtures. A frozen timetable stops being true
  within the hour.
- Anything that makes journey search *fail* when punctuality is down.

## Principles

- **Absence degrades, it never fails.** No punctuality service, no ingest, no cell for
  this train at this hour — the score stays `None` and the search returns exactly what
  it returned before the field existed.
- **A guess that looks like a measurement is worse than a blank.** Turning `DRB → RB`
  from the shape of the string converts absent data into a confident number, which is
  the exact failure the reliability field is shaped to avoid.
- **The fixture is generated by the stack it tests**, so it moves with the dependency
  instead of freezing a byte layout nobody can regenerate.

## Constraints

- **C1** — a capability depends on another's contract, not its code. transit reaches
  punctuality over HTTP and never links the crate.
- **C2** — the real parquet files are private and 100+ MB. Nothing under
  `<overlay>/data/punctuality/raw/` may be committed or cited as a test input.
- **C3** — `bazel test //...` is the gate. `//:architecture_up_to_date_test` is the only
  check that catches a stale generated `ARCHITECTURE.md`, and running everything else
  and reporting green is how main sat red across three commits on 2026-08-19.
- **C4** — `Packs/travel/design/` is untracked on purpose via `.git/info/exclude`, and
  the brainstorm carries an absolute `/Users/...` path the publication-hygiene gate
  rejects. This ISA is tracked; those three documents are not.

## Goal

Reliability scores on the default backend for regional legs, on evidence rather than
inference, and a parquet reader whose next arrow bump is verified by running a test.

## Features

### F1 · Reliability survives the default path

Why: the number is already computed correctly and then discarded on the path almost
every real search takes.

- [x] ISC-1 — dbnav is the default rail backend: `RailBackend::default()` is `DbNav`,
  and with `AXON_TRANSIT_BACKEND` unset a live search whose arriving transfer leg is
  regional returns a non-null `reliability`. Evidence: Bonn→Berlin 2026-08-24T09:00,
  `reliability.probability` 0.4374 over the RE5 + ICE 557 chain, `min_sample` 1327.
- [x] ISC-2 — an unresolvable train type is explicitly absent, not silent: the response
  names the legs it could not ask about, so a reader can tell "no data" from "no risk"
  and "punctuality had no cell" from "nobody asked". Evidence: same search forced to
  dbweb returns `reliability: null` beside `unscored_legs: [{leg_index: 0, train_name:
  "28510", train_category: "DRB"}]`.
- [x] ISC-3 — the train type punctuality is asked for is checked against observed data
  on both sides, never inferred from a class code. Landed as the identity rather than a
  table: `train_type_of` reads the label off `train_name`, and all eleven prefixes seen
  live (ICE, RE, IC, S, RB, EC, RJ, FEX, FLX, EUR, ECE) exist in the ingested cells, so
  nothing needed translating. Evidence: 104 legs over 16 routes on both backends,
  2026-08-20; `the_train_type_is_the_label_not_the_product_class`.
- [~] ISC-4 — **refuted, and kept as the record of why.** dbweb cannot score its
  regional legs at all: it names them by bare number (`"28510"`), so no label exists to
  read a type off, and its `kategorie` reports `DRB` for both the RE5 and the RB26 —
  one class code over two populations punctuality holds apart at 10.8M and 14.4M
  observations. There is no correct mapping to build. What replaced this claim is
  ISC-2: dbweb says so explicitly instead of returning a bare null.
- [x] ISC-5 — the stale seam comment is gone: no doc comment references
  `dbnav_split_unsupported`, a symbol deleted when split-ticketing stopped being
  dbweb-only (`cdacfbf`). Falsifier: `rg dbnav_split_unsupported` hits.

### F2 · The parquet reader proves itself

Why: it is the one component whose whole job is reading someone else's format, and it
was the only one no test exercised — so every arrow bump was hand-verified against a
private file, or not verified.

- [x] ISC-6 — a miniature parquet fixture is *generated* by `parquet`'s own `ArrowWriter`
  and folded to known cells by a test. Six rows, written to the test's own scratch dir,
  never the private data dir. Evidence:
  `folding_a_file_lands_every_row_in_the_bucket_it_belongs_to`; suite 29 → 31 tests.
  (Scaffolded as "committed" — see Decisions, 2026-08-20.)
- [x] ISC-7 — a missing column produces `IngestError::MissingColumn`, proven red-then-green
  for each of the five required columns and asserted to name the one that went. Evidence:
  `a_dropped_column_is_named_rather_than_panicked_or_silently_zeroed`, which ends on the
  complete file folding, so the red is the column and not the fixture. (This path already
  fired once upstream, 2026-05, per `upstreams.toml [deutsche-bahn-data]`.)
- [x] ISC-8 — a cancellation counts in `canceled` and stays out of `n`, and a row with
  neither a delay reading nor a cancellation flag lands in `skipped`. Proven non-vacuous
  by mutation: making `Cell::record` fold a cancellation in as 0 minutes late turns the
  suite red, reverting turns it green.
- [x] ISC-9 — a timestamp that came out of a file folds to the right local hour and
  weekend flag, not only synthetic integers. Evidence: the Saturday 09:00 and Monday
  17:00 cells are asserted by full key, both read back through parquet.

## Not yet specified

In scope, too dim to state as a claim yet.

- **L1 · one outcome record.** `POST /api/plans/:id/outcome` after the next real trip.
  Not code. Gates L2's transfer-buffer calibration and the independence assumption
  journey reliability currently states rather than corrects.
- **`is_regional` disagrees between the backends, and dbweb looks wrong.** Same RE5
  Bonn→Köln, same search, 2026-08-20: dbnav reports `is_regional: true`, dbweb reports
  `false`. dbweb derives the flag from the `9G` entry in `zugattribute`, which was absent
  on this response; dbnav derives it from the product class. The flag decides whether a
  leg is presented as Deutschlandticket-covered, so a false negative sends a traveller to
  buy a ticket they already hold. Found while measuring the train-type vocabulary, not
  chased: it needs its own spread of routes before the falsifier is worth stating, since
  one absent attribute on one train is not yet a pattern.
- **Recovering a type for dbweb's regional legs.** Both backends agree on
  `train_number` (`28510` is the RE5 on each), so a number→label resolution would make
  dbweb scorable. It costs a second lookup against something that holds the mapping, and
  nothing in the system holds one today. Parked rather than dismissed: the default path
  no longer needs it.
- **The cancellation flag end to end.** `originCancelled`/`destinationCancelled` are
  captured from a real section and fixture-tested; no cancelled train has appeared in a
  live response yet. Opportunistic — keeping the vocabulary and waiting costs nothing.
- **`bodies_without_schemas` as a build gate.** Fourteen routes have undeclared bodies.
  Failing the build on all fourteen today blocks work rather than directing it.
- **Obsidian export.** Gated on there being something machine-derived worth exporting,
  which is still L1.

## Anti-claims

- [x] A1 — no mapping entry is inferred from the shape of the string. Held by there
  being no mapping at all: the label is the type, and where there is no label the answer
  is absence.
- [x] A2 — journey search never fails because punctuality is absent. `unscored_legs` is
  written before the lookup, so it survives the service being down — which is also what
  makes `an_unscorable_leg_is_reported_rather_than_left_silent` assertable without one. Falsifier: stop
  punctuality-server, search returns anything other than 200 with a null score.
- [x] A3 — no new tracking surface. Falsifier: a `TODO.md`, `PLAN.md`, `HANDOFF.md` or
  `ROADMAP.md` appears anywhere under `Packs/travel/`.

## Decisions

- **2026-08-20 — the category was never the key.**
  - *Conjectured:* dbweb's `kategorie` needed a checked equivalence table onto
    punctuality's `train_type`, and dbnav's `produktGattung` already was that vocabulary.
  - *Refuted by:* 104 legs over 16 routes, both backends, against the 109 distinct
    `train_type` values in the cells. dbweb reports `DRB` for both the RE5 (`28510`) and
    the RB26 (`33602`), so the distinction the table would need was already thrown away.
    dbnav collapses the same way — `RB` for an RE5, `IC_EC` for both IC and EC — and it
    *found* a cell, answering an RE journey with RB statistics. Worse than absence.
  - *Learned:* punctuality's vocabulary is the train's own label, and both backends carry
    it in `train_name`. All eleven observed prefixes exist in the cells; none needed
    translating. dbweb's regional legs carry no label at all, which is why they are
    genuinely unanswerable rather than merely unmapped.
  - *Criterion now:* ISC-3 is the label resolver checked against both sides, and ISC-4 is
    refuted rather than deferred.
- **2026-08-20 — the parquet fixture is generated, not committed.** ISC-6 was scaffolded
  as "committed" before the reader had been read. A checked-in blob would freeze a byte
  layout nobody could regenerate once the crate moved, which is the opposite of what the
  claim wanted: that the test move WITH an arrow bump. Writing it through the same
  `ArrowWriter` the reader reads through does that, keeps the private 100+ MB files out,
  and makes the five missing-column variants free. Recorded rather than silently reworded.
- **2026-08-19 — dbnav becomes the default.** It fixes the path real searches take, and
  its own vocabulary bug is fixed by the same resolver.
- **2026-08-19 — this file replaces the travel issues.** #185 and #186 were closed into
  F1 and F2 rather than tracked in parallel.
